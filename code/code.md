# Research Question 1 (RQ1)

This code provides a graphical user interface (GUI) application for analysing the toxicity of responses generated by
large language models (LLMs). The tool allows users to load different models, provide prompts, and evaluate the toxicity
of the generated responses using Google's Perspective API.

This GUI was initially implemented using `Tensorflow` along with `Keras-hub`. This however, was found to be too resource
and time intensive when trying to prompt the models, taking about 2-5 minutes per prompt. After this realisation, the
decision was made to use `Ollama` for the large inference tasks. This brought processing time down by multiple orders of
magnitude, bringing the processing time per prompt down to 0.5-1.5 seconds per prompt. This made a large part of RQ1
possible. The older `Keras` implementation can be found in `keras-archive`.

## Features

- **Model Selection**: Choose from a list of pre-configured models to load and query.
- **Ollama Framework**: Uses Ollama serve for easy and efficient model loading and inference
- **Prompt Management**: Load prompts from a JSON file for batch processing.
- **Response Scoring**: Analyse the toxicity of model-generated responses using the Perspective API.
- **Result Management**: Save results to a JSON file for later analysis.

## Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/rbithray/CapstoneAI-Toxicity
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Set up the Google Perspective API:
    - Obtain an API key from [Google Cloud Console](https://console.cloud.google.com/).
    - Save the key in the `../secrets` directory (or adjust the code to point to your preferred location).

> [!NOTE]
> For correct functionality make sure the `secrets` file follows the following format:
> ```json
> {
>   "PerspectiveAPI":{
>     "key": "YOUR_API_KEY"
>   }   
> }
> ```

4. Install and start the Ollama server for model management:
    - [Ollama Documentation](https://ollama.ai/docs).

## Usage

### Running the Application

1. Start Ollama serve
   ```bash
   ollama serve
   ```
2. Start the GUI:
   ```bash
   python main.py
   ```

3. Use the GUI to:
    - Select and load a model (optional: add a system prompt at this stage).
    - Load prompts from a JSON file.
    - Run prompts through the model and evaluate the responses.
    - Save the results to a JSON file.

### Prompts File Format

The prompts file should be a JSON file with the following structure:

```json
{
  "text": {
    "prompt1_id": "Prompt text 1",
    "prompt2_id": "Prompt text 2"
  },
  "toxicity": {
    "prompt1_id": 0.1,
    "prompt2_id": 0.5
  }
}
```

### Results File Format

Results are saved as a JSON file with entries for each processed prompt:

```json
[
  [
    "Prompt text 1",
    "Prompt 1 response",
    0.011
  ],
  [
    "Prompt text 2",
    "Prompt 2 response",
    0.092
  ]
]
```

## Key Functions

### `load_model`

Loads a specified model, supporting both local and remote model management via the Ollama server.

### `get_responses_scores`

Processes a list of prompts, queries the model for responses, and evaluates the toxicity scores. Includes retry
mechanisms for empty responses.

### GUI Buttons

- **Load Model**: Loads the selected model.
- **Kill Model**: Unloads the currently loaded model.
- **Load Prompts**: Opens a file dialog to load prompts from a JSON file.
- **Run Prompts**: Processes the prompts through the loaded model and evaluates the responses.
- **Save Results**: Saves the processed results to a JSON file.

---

## Error Handling

- **Model Loading**: Alerts users if the model fails to load or the Ollama server is unavailable.
- **Empty Responses**: Retries generation for empty responses up to a maximum number of retries, then skips the prompt
  if still unsuccessful.
- **API Errors**: Catches and logs errors from the Perspective API.

# Research Question 2 (RQ2)


This code demonstrates the use of a large language model, for analyzing and interpreting model outputs using Captum. It is designed to run on a Kaggle environment with GPU acceleration, utilizing libraries for data processing, deep learning, and model interpretability.

---
## **Code Explanation**

This repository provides a workflow for generating text with large language models and analyzing its outputs using interpretability techniques from Captum.

### **1. Model Setup**
- **Loading the Model:** 
  - The model is loaded with **4-bit quantization** using `BitsAndBytesConfig` for efficient GPU usage.
  - The model and tokenizer are initialized in the `load_model` function.
- **Text Generation:**
  - The `get_BLOOM` or `get_output` function generates text from a given prompt using the model.
  - Randomness is controlled via `temperature`, `top_k`, and `do_sample`.

### **2. Interpretability Methods**
The code employs Captum to analyze the importance of tokens in the model's output:
- **Feature Ablation:** 
  - Evaluates token contributions by systematically removing them.
  - Token and sequence-level importance are visualized.
- **Shapley Values:** 
  - Uses Shapley value sampling, a cooperative game-theoretic method, to estimate token importance.
- **Integrated Gradients:** 
  - Computes gradients of the output with respect to the embeddings to assess token impact. <br>
  
 We eventually settled on only using **Feature Ablation** in our final project.

### **3. Input Representation**
- The `TextTokenInput` class processes text into tokenized inputs compatible with Captum’s attribution methods.

### **Purpose**
This code allows users to:
1. Generate text using Bloom or Llama, Mistral and Gemma.
2. Apply interpretability techniques to visualize and understand token importance.
3. Gain insights into the model's decision-making process.
